# OAS 点击分布分析器

双击 **点击分布分析器.html** 即可使用。不需要安装依赖，不需要启动 OAS，也没有网络请求、上传或遥测。支持 Edge、Chrome 等现代浏览器。

## 使用

1. 选择 OAS 的 `log` 文件夹中的一个或多个 `.txt` 文件，例如 `2026-10-02_小号1.txt`。也可粘贴日志，或先加载演示。
2. 选择任务、角色/账号、OAS 配置。账号与配置是不同维度：一个配置可以处理多个角色。
3. 确认画面尺寸。日志里只有一种 `[Screen_size]` 时自动填入；没有尺寸时默认 1280×720，需人工核实。坐标原点在左上角，X 向右、Y 向下。不同尺寸的明确标记记录会被排除，不会自动缩放混合。
4. 可指定时间范围，如 `18:00:00` 至 `18:05:00`，也可填完整日期 `2026-10-02 18:00:00`。结束时间不带毫秒时包括该秒的全部记录。仅时分秒的跨午夜范围，如 `23:50:00` 至 `00:10:00`，会匹配各天相应时段；要指定某天请使用完整日期。
5. 切换黑底红点散点图、网格热力图、时间轨迹。点击地图或高频区域行，筛选该网格的原始记录。
6. 导出当前图 PNG、全部筛选记录 CSV 或统计 JSON。记录分页只影响显示，CSV 不限于当前页；CSV 包含区域筛选，JSON 的总体指标按任务/账号/时间筛选计算，另附区域筛选标记。

每次导入替换当前数据。一次最多 64 MB；更大日志请分批。UTF-8 为默认编码，旧中文日志可切换 GB18030 / GBK。工具不自动合并/去重日志副本，勿同时导入日常日志与其中截取的错误日志。

## 统计定义与限制

- 有效点击：当前筛选中，坐标有限、状态为 attempted/sent、尺寸匹配、且 `0 ≤ x < width, 0 ≤ y < height` 的记录。越界、尺寸不一致、解析错误单独报告。
- 精确重复比例：`(有效点击数 - 唯一坐标数) / 有效点击数`。按配置、账号、设备分别比较，再汇总分母。未知账号仅同文件、同会话比较，以免把不同账号误归为同一个。
- 近似重复比例：与此前至少一个点满足 `|Δx| ≤ 容差` 且 `|Δy| ≤ 容差` 的点击数 / 有效点击数。包括精确重复；不是圆形距离，也不是固定网格聚类。判断顺序为导入文件顺序和各文件原始行序。
- 高频区：固定网格次数、最高频区占比、前五区占比。边界用半开区间 `[开始,结束)`；热力色阶使用 `log(1+次数)`，数字为原始计数。
- HHI：`Σ (网格点击数 / 总点击数)²`，0 表示无数据；有数据越接近 1 越集中。等效区域数为 `1 / HHI`。不同网格大小下结果不宜直接比较。
- 同区连续次数：同来源/配置/账号/设备/任务/会话内、按导入行序连续落在同一个网格的最长次数。用于排查重复操作，正常确认按钮也可能有高值。
- 轨迹：分别在同来源/配置/账号/设备/任务/会话/尺寸内按时间排序；相同时间以原行号排序。如果该会话存在缺失时间，或混用完整日期与仅时间记录，整段按原始行序显示。只有时分秒时，超过 12 小时的回退当作跨午夜，小幅回退作为乱序保留以供排序。
- 已有 OAS 点击日志是**发送前的请求坐标/尝试时间**，不能证明输入已到达游戏、按钮被接受或与底层最终注入点完全一致。后端重试、绕过统一函数但未记录的直接调用也无法从缺失日志还原。
- 导入源文件应保持各配置独立。单个交错混合、缺少配置/账号逐行标识的日志无法可靠还原归属，工具不推断未记录的信息。
- 数字 Unix 时间戳不猜测秒/毫秒单位。结构化日志请使用 ISO 8601 字符串。带时区的结构化轨迹按实际时间排序；仅时分秒筛选按日志显示的本地时间。无时区 OAS 日期按日志墙上时间比较。

## 结构化日志与 CSV 格式

JSONL（每行一条，可独立文件，也支持 `CLICK_EVENT {...}` 消息）：

```json
{"event":"click","time":"2026-10-02T18:00:00.123+08:00","x":834,"y":621,"task":"courtyard","account":"角色A","profile":"小号1","device":"设备1","button":"FIRE","width":1280,"height":720,"session":"run-1","status":"sent"}
```

仅 `event/type` 为 `click/tap/点击` 才计入，避免把截图/OCR 坐标当点击。状态 `failed` 等列入诊断，不计入地图。`sent` 表示输入调用返回，不证明业务成功。纯 JSON 数组不是 JSONL，需按一条事件一行导出。

CSV 必须有 `x,y` 列，支持 `time/timestamp,task,account,profile,device,button/target,width,height,status,session`。支持引号、逗号和多行字段。导出会为可能被电子表格解释为公式的文本添加前导单引号。

## 如其他版本没有坐标日志：最小埋点方案

当前 OAS 不需要应用以下方案。仅作后续诊断设计，不自动修改正式文件。

1. 在统一点击发送点，最终坐标确定以后记录 JSON 事件，保留现有调用、坐标、校验、节奏与异常处理。只记录数据，不修改点击决策或动作。
2. 优先单独启用诊断日志开关，使用现有 logger 输出 `CLICK_EVENT ` 加 `json.dumps(event, ensure_ascii=False)`，确保文件级别允许 INFO。默认关闭，避免长期日志量增加。
3. 调度/角色成功切换处维护 task、account、profile、session 上下文；未知填空。不要把准备切换的目标账号提前当作已登录账号。截图维度取点击对应坐标空间的实际截图尺寸。
4. 若只需发送前尝试，标 `status=attempted`；若需要发送结果，在原方法返回后标 `sent`，异常时标 `failed` 并原样重新抛出。记录中的时间是对应阶段的时间。不要把尝试与发送结果都记作两次点击；使用一个独立事件流或用事件 ID 对齐。
5. 检查绕过统一 click 的直接后端调用（如百鬼路径），必要时在实际发送点同样记录，避免上层和后端双重计数。仅在完成代码审阅与用户批准后修改正式 OAS。
6. 一次点击一条事件，写入失败不得吞掉原点击异常或引起追加点击。输入调用返回也不等于游戏接受，不用点击图推断未记录结果。

这是一套只读调试/集中区域诊断方案，不提供点击伪装、检测阈值或绕过检测功能。

## 开发与验证

用户使用仅需要 HTML 文件。其余是可维护源码、测试与说明；Node 仅用于开发。

```powershell
node build.js
node --test test.js
node validate-local.js 'D:\Entertainment\Tool\OAS\log'
```

`validate-local.js` 不导入 OAS 模块；仅读取日志，并在工具目录生成统计验收 JSON。源码与构建产物相互独立，源码改动后需重新运行 build.js。
